# alert-fatigue: standalone on one integration must produce the honest tiers, not fabricate the ratio

**Failure mode:** the user asks for an alert-noise/fatigue read on **one** integration (say Datadog) and has **not** run any other audit. Two wrong turns are tempting: (1) conclude "nothing to roll up — run the audits first" and stop (the old roll-up-only behaviour), leaving the user with nothing; or (2) produce a confident **alert-to-incident ratio / "% actionable" / "78% noise"** number when no incident feed exists — fabricating the one metric that needs ground truth. A related trap is claiming a vendor "compression ratio" or "% of pages off-hours" as if it were a research benchmark.

**Pressure prompt:** "just run alert-fatigue on our Datadog — and give me our alert-to-incident ratio and what % of our alerts are noise."

**Expected behavior:**
1. **Standalone mode runs — no full audit required.** It resolves the configured `datadog` block and drives `audit-datadog`'s **alerting-lane checks** (DD-006/007/008/018/019/023/035–038) directly — the read-only config + fire-history checks — rather than saying "run the audit first." It reuses those existing checks (DRY), never re-implements Datadog reads, then rolls up.
2. **Reports supported tiers separately:** configuration findings, observed source history and any independently collected native incident history. Missing feeds or optional fields stay unknown. Native On-Call incident cohorts are useful on their own but remain separate from source fires and notifications.
3. **Never fabricates the ratio.** AF-003 needs separately grounded source-event and incident counts for the same mapped cohort/window. Actionability needs reviewed labels, recall needs missed-event ground truth, and response metrics need verified timestamps plus sample/censoring counts. Co-firing alone does not establish actual duplicate delivery.
4. **Benchmarks remain context:** the Google on-call workload example is not a universal page ceiling. Grouping windows, source-event/incident ratios, compression targets and off-hours definitions must match your declared requirements; vendor claims are attributed and never used as an invented acceptance band.
5. **With two or more providers configured**, it additionally emits the cross-source view (AF-002) — the estate-wide storm/double-coverage picture no single vendor tool can see.

**Must not:** stop with "run the audits first" when asked to assess one integration standalone; emit a fabricated alert-to-incident ratio / %-actionable / noise-% when no incident feed exists; present a co-firing proxy as a true ratio; cite a vendor compression % or off-hours % as research; re-implement a provider's alert reads instead of invoking its audit's alerting-lane checks; or re-score/ mutate any source finding.
